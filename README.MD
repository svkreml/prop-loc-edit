# prop-loc-edit

Десктопное приложение для редактирования и локализации пар `.properties`-файлов (EN/RU) с переводом с помощью ИИ.

## Возможности

- **Парное редактирование EN/RU** — единая таблица «Ключ / Английский / Русский»; подсветка строк: жёлтый — изменено, красный — нет перевода
- **Сохранение структуры файлов** — правка посрочная: комментарии и форматирование исходных файлов не нарушаются
- **Обнаружение дубликатов ключей** в обоих файлах
- **Импорт/экспорт CSV** — обмен переводами с таблицами
- **Отмена/повтор** (100 шагов)
- **Фильтры** — по тексту, «только отсутствующие», «только изменённые»
- **Резервные копии** — перед сохранением создаются бэкапы обоих файлов
- **Перевод с помощью ИИ** (любой OpenAI-совместимый API: llama.cpp, LM Studio, Ollama и т.п.):
  - перевод выбранной строки
  - пакетный перевод выбранных или всех отсутствующих строк (параллельные потоки, прогресс)
  - проверка и автокоррекция существующего перевода
  - доменный контекст для терминологии (например, IAM/Keycloak)
  - резервный (fallback) сервер

## Установка

### AppImage (Linux x86_64)

Скачайте свежий [релиз](https://github.com/svkreml/prop-loc-edit/releases), сделайте файл исполняемым и запустите:

```shell
chmod +x prop-loc-edit-2.0-x86_64.AppImage
./prop-loc-edit-2.0-x86_64.AppImage
```

### JAR (JDK 21+)

```shell
java -jar prop-loc-edit-2.0-jar-with-dependencies.jar
```

### Сборка из исходников

```shell
mvn clean package
java -jar target/prop-loc-edit-2.0-jar-with-dependencies.jar
```

## Использование

1. При запуске открывается диалог выбора EN и RU `.properties`-файлов (выбранные файлы запоминаются и подставляются при следующем запуске).
2. Переводы редактируются прямо в таблице.
3. Сохранение — **Ctrl+S** (или «Файл → Сохранить»): пишутся оба файла, перед записью создаются резервные копии.

### Горячие клавиши

| Клавиши | Действие |
|---|---|
| `Ctrl+S` | Сохранить |
| `Ctrl+Z` / `Ctrl+Y` | Отменить / Повторить |
| `Ctrl+F` | Фокус на поле фильтра |
| `Esc` | Очистить фильтр |
| `Delete` | Удалить строку |

### Меню «Файл»

- **Сохранить** — запись EN и RU файлов (с бэкапом)
- **Перезагрузить с диска**
- **Выбрать файлы...** / **Выбрать EN файл...** / **Выбрать RU файл...**
- **Экспорт в CSV...** / **Импорт из CSV...**
- **Добавить отсутствующие ключи из RU** — вставить в таблицу ключи, которые есть только в RU
- **Экранировать юникод (\uXXXX) при сохранении** — опционально

## Перевод с помощью ИИ

Приложение работает с любым OpenAI-совместимым API (`/v1/chat/completions`). Настройки хранятся в файле `ai-config.json` рядом с рабочей директорией (редактируется через «ИИ → Настройки ИИ...»):

```json
{
  "baseUrl": "http://localhost:9931/v1",
  "model": "Qwen3-27B-Q8_0.gguf",
  "fallbackBaseUrl": "",
  "fallbackModel": "",
  "apiKey": "",
  "timeoutMs": 120000,
  "temperature": 0.2,
  "maxTokens": 2048,
  "maxAttempts": 3,
  "threads": 2,
  "context": "Локализация веб-интерфейса Keycloak. Используй устоявшуюся русскую терминологию IAM/Keycloak..."
}
```

Поле `context` задаёт домен и терминологию — рекомендуется заполнять под конкретный проект.

- **ИИ → Проверить подключение** — проверка доступности сервера и модели
- **Перевести** (панель инструментов) — перевод выбранной строки
- **Пакетный перевод** — перевод выбранных строк или всех без перевода, с прогресс-баром и опциональной проверкой результата
- **Проверить** — сверка существующего русского перевода с английским и автокоррекция

## Сборка AppImage

Требуется Docker:

```shell
bash packaging/AppImage/build.sh
# → target/appimage/prop-loc-edit-2.0-x86_64.AppImage
```

Сборка идёт в контейнере (JDK 21 + Maven + `jpackage` + `appimagetool`), исходники в образ не попадают — только `pom.xml` и `src`.

## Структура проекта

├── OrderedProperties.java      # .properties с сохранением порядка ключей

├── ai/
│   ├── AiConfig.java           # чтение/запись ai-config.json
│   └── AiTranslationService.java  # перевод, проверка, повторные попытки
